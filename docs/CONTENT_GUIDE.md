# Руководство по учебным материалам

Системные требования к публикации заданы в `../specs/system.spec.md`. Этот файл
описывает авторский формат одного урока.

## Файл и frontmatter

Для каждого урока создаются два файла:

```text
src/content/lessons/ru/<slug>.mdx
src/content/lessons/uk/<slug>.mdx
```

Пример:

```mdx
---
title: "Название темы"
description: "Описание для поисковой выдачи"
language: "ru"
section: "dc"
slug: "topic-slug"
order: 1
duration: 45
keywords:
  - ключевая фраза
draft: false
---

Вводный индексируемый текст.
```

Парные файлы используют одинаковые `section`, `slug`, `order`, `duration` и
статус публикации. Значения `language`, `title`, `description`, `keywords` и
основной текст локализуются. Украинский технический код — `uk`, не `ua`.

## Рекомендуемая структура урока

1. Цель и предварительные знания.
2. Теория и определения.
3. Расчётная схема.
4. Исходные данные.
5. Составление уравнений.
6. Подробный вывод.
7. Учебное объяснение.
8. Краткое практическое решение.
9. Проверка результата.
10. Типичные ошибки и связанные темы.

## Три уровня

- `1 — Исследователь`: полный вывод и обоснование;
- `2 — Объяснение`: методика и ключевые шаги;
- `3 — Только решение`: формулы, подстановка и ответ.

Пока универсальный renderer не реализован, не копируй целиком
`legacy-pages/MeshLesson.tsx` для каждого урока. Сначала выполни этап `ET-02` из
`ROADMAP.md`.

## Формулы, схемы и источники

Формулы записываются для KaTeX. Схемы перерисовываются в SVG с прозрачным фоном
и семантическими цветами, работающими в светлой и тёмной теме.

Word, PDF и фотографии сначала распознаются и проверяются. Неясные индексы,
знаки, направления стрелок и числовые значения требуют подтверждения автора;
их нельзя достраивать предположением.

## Проверка публикации

- RU/UK-пара существует;
- frontmatter проходит схему;
- `slug` и `section` совпадают;
- формулы и SVG читаемы в обеих темах;
- текст виден в статическом HTML;
- каталог не помечает отсутствующую тему доступной;
- `pnpm check` и `pnpm build` проходят.
