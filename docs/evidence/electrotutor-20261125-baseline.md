## Контракт для следующей реализации

Операции выполняются над нормализованным графом с устойчивыми ID. Planner получает неизменяемый снимок и границы операции из `topology-session.ts`. Валидатор проверяет ссылочную целостность, отсутствие неявного слияния цепей и допуски адаптера. Успешный commit публикует один снимок с одной записью Undo. Ошибка оставляет граф, Undo/Redo и ранее показанный результат доступными. Геометрия и масштаб находятся в отдельной части документа и используют электрическую связность для отображения. Диагностика solver не отменяет допустимый разрыв, КЗ или незавершённый редактируемый опыт.

Правило LC принимает подграф и упорядоченные граничные выводы. Оно возвращает отказ с кодом причины либо неизменяемый план замены с ID правила, ценой, стабильной сигнатурой, новыми номиналами в SI и результатом проверки полной портовой функции. Журнал шага включает ID исходных и новых компонентов, границы, значения и единицы, формулу, способ проверки и статус. Синтез всей схемы публикует отдельно рациональную функцию, извлечённые звенья и новое представление. Граф меняется только при подтверждённом действии.

Входящий архив проходит действующие ограниченные валидаторы до замены состояния. В рабочем профиле проходят импорт старых LC-деревьев, переоткрытие схем после редактирования, roundtrip версии 1, Undo и защита неизвестной версии. Корневой E2E зафиксировал отдельный сбой повторного импорта LC после перезагрузки. Следующие изменения проверяют старые fixtures с неизменным netlist и параметрами. Для отчётов используются стабильные ID требований, команда, ревизия, результат по случаям, браузер/размер кадра и пути к fixture, JSON и кадрам. Исходные и итоговые артефакты получают разные каталоги в `playwright-report/master-20261125/`.
