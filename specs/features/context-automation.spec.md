# Спецификация автоматизации контекста и этапов

Статус: Действует

Версия: 1.1

## 1. Назначение

Обеспечить продолжение разработки Electro Tutor из нового сеанса Codex одной
короткой командой без загрузки всего репозитория и без конкурирующих источников
истины.

## 2. Область

- канонические роли Markdown-документов;
- маршрутизация контекста через `AGENTS.md`;
- выбор следующего незавершённого этапа;
- выполнение одного ограниченного этапа за запуск;
- синхронизация `AI_PLAN`, `AI_STATUS` и `ROADMAP`;
- воспроизводимая инструкция визуальной проверки результата.

## 3. Вне области

- копирование глобальных agents, Skills, hooks, MCP или Git workflow в проект;
- автоматическое слияние веток, push, PR или deploy;
- реализация нескольких независимых roadmap-этапов одной командой;
- подмена SPEC текстом prompt-файла.

## 4. Функциональные требования

### FR-CTX-001 Канонические источники

Каждая роль должна иметь один источник: требования — `specs/`, устройство —
`docs/ARCHITECTURE.md`, решения — `docs/DECISIONS.md`, дизайн —
`docs/DESIGN.md`, безопасность — `docs/SECURITY.md`, порядок этапов —
`docs/ROADMAP.md`, текущая работа — `docs/AI_PLAN.md`, фактическое состояние —
`docs/AI_STATUS.md`.

### FR-CTX-002 Команда продолжения

Команда `Продолжай Electro Tutor` должна запускать протокол из
`prompts/STAGES.md`. Если `AI_PLAN` имеет статус `PLANNED` или `IN_PROGRESS`,
исполнитель продолжает его; иначе выбирает первый `PLANNED` stage с завершённым
dependency DAG. `BLOCKED` и `OPTIONAL` не выбираются автоматически.

### FR-CTX-003 Минимальный контекст

Исполнитель читает ближайшие инструкции, индекс SPEC, затрагиваемую SPEC,
релевантные проектные документы, текущий план и компактный статус. Остальные
источники загружаются только по необходимости.

### FR-CTX-004 Один ограниченный этап

За один запуск исполнитель планирует при необходимости и завершает не более
одного подэтапа с явной областью файлов, критериями приёмки и проверками.

### FR-CTX-005 Блокирующие решения

Если следующий этап требует production-домена, юридической модели, платёжного
провайдера, учётной записи или другого пользовательского решения, исполнитель
не придумывает значение и не перескакивает к зависимому этапу. Он завершает
доступную безопасную подготовку либо сообщает один точный блокер.

### FR-CTX-006 Завершение

После этапа исполнитель обновляет только фактически изменившиеся документы,
запускает соразмерные проверки, создаёт commit и не выполняет merge без явного
разрешения пользователя.

### FR-CTX-007 Наглядная проверка

После каждого этапа исполнитель сообщает, как увидеть результат воочию: точную
команду запуска, URL, действия в интерфейсе или DevTools и ожидаемое состояние.
Для невизуального изменения указывается ближайшее наблюдаемое доказательство.

### FR-CTX-008 Переносимое продолжение

Критический контекст должен восстанавливаться на другом компьютере из Git и
глобального ДЕВ без старого чата и machine-local prompt. Workflow обязан
проверять clean/dirty состояние, явно переключаться на выбранную ветку,
получать её только fast-forward, восстанавливать pinned dependencies через
frozen lockfile, валидировать context route/overlay и только затем читать статус
и продолжать один stage.

## 5. Нефункциональные требования

- NFR-CTX-001: project overlay не дублирует workspace-инструкции.
- NFR-CTX-002: все внутренние Markdown-ссылки указывают на существующие файлы.
- NFR-CTX-003: проектный человекочитаемый контекст ведётся на русском языке.
- NFR-CTX-004: prompt-файл не является источником требований продукта.

## 6. Критерии приёмки

- AC-CTX-001: в корне нет дублирующих `PROJECT_CONTEXT.md` и архитектурного
  документа, конкурирующего с `docs/ARCHITECTURE.md`.
- AC-CTX-002: обязательные SPEC/docs существуют и имеют однозначные роли.
- AC-CTX-003: `AGENTS.md` распознаёт команду `Продолжай Electro Tutor`.
- AC-CTX-004: `prompts/STAGES.md` описывает выбор, выполнение, проверку
  и закрытие одного этапа.
- AC-CTX-005: аудит ссылок и `git diff --check` проходят без ошибок.
- AC-CTX-006: протокол закрытия требует раздел «Как увидеть изменения воочию».
- AC-CTX-007: новый session по repository-relative ссылкам находит текущий
  `AI_PLAN` либо первый допустимый `PLANNED` stage и не выбирает `BLOCKED`.
- AC-CTX-008: README содержит безопасный ПК ↔ ноутбук workflow с
  явным branch selection, `--ff-only`, `--frozen-lockfile`, context route и
  project overlay validation.
