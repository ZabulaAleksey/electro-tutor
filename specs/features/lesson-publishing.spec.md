# Спецификация единой публикации уроков

Статус: Действует

Версия: 1.0

## 1. Назначение

Определить один проверяемый источник истины для опубликованных уроков, их
локализованных маршрутов, доступности в каталоге и необязательных интерактивных
компонентов.

## 2. Область

- парные RU/UK-записи Astro Content Collection `lessons`;
- manifest опубликованных уроков;
- доступность и ссылки темы на главной странице и в каталоге;
- универсальный маршрут `/[lang]/topics/[section]/[slug]/`;
- видимый статический MDX-контент;
- статический registry разрешённых React islands.

## 3. Вне области

- создание новых учебных материалов;
- перенос полного legacy-урока в MDX за один этап;
- редактор контента, CMS и динамическая публикация;
- новые типы интерактивов и изменение их визуального дизайна;
- аккаунты, платежи и production deploy.

## 4. Участники

- автор добавляет парные RU/UK MDX-файлы и проверяемые метаданные;
- ученик открывает доступную тему в выбранной локали;
- поисковый робот получает индексируемый текст без выполнения JavaScript;
- сборка отклоняет некорректные метаданные и неизвестный interactive key.

## 5. Предусловия

- Content Collection `lessons` валидирует frontmatter;
- contract-тесты проверяют уникальность и RU/UK-парность;
- `draft: true` исключает запись из публичной публикации;
- curriculum остаётся источником порядка, группировки и локализованных названий
  карточек, но не статуса публикации.

## 6. Функциональные требования

### LP-FR-001 Manifest опубликованных уроков

Система должна строить manifest только из записей `lessons` с `draft: false`.
Публичный ключ записи — `language/section/slug`. Manifest должен предоставлять
типизированные `language`, `section`, `slug`, `href` и метаданные урока,
необходимые маршруту.

### LP-FR-002 Локализованная доступность

Карточка curriculum считается доступной в конкретной локали только при наличии
соответствующей опубликованной записи manifest. Доступная карточка ведёт на
собственный `section/slug`; недоступная карточка не получает ссылку на чужой
или резервный урок. Связь задаётся optional полем curriculum `lessonSlug`; `id`
темы остаётся UI-идентификатором и не обязан совпадать со slug публикации.
Section берётся от родительского раздела curriculum. При отсутствии
`lessonSlug` тема считается непубликуемой и остаётся без `href`.

### LP-FR-003 Парная публикация

Опубликованный урок должен иметь согласованную RU/UK-пару согласно системной
SPEC и content contract. Публикация одной локали без второй должна отклоняться
штатным test gate.

### LP-FR-004 Универсальный маршрут

Маршрут урока должен отрисовывать выбранную запись Content Collection и не
зависеть от конкретного slug. Заголовок, описание и основной MDX-контент должны
попадать в статический HTML.

### LP-FR-005 Необязательный интерактив

Frontmatter может содержать необязательный ключ `interactive` из закрытого
набора разрешённых значений. При отсутствии ключа маршрут отображает обычный
MDX без React island. Для `mesh-current-method` разрешён ключ `mesh-lesson`,
сохраняющий существующий интерактив.

### LP-FR-006 Безопасный registry

Interactive component выбирается только из статического типизированного
registry. Произвольный путь или динамический `import()` из значения frontmatter
не допускается. Неизвестный ключ должен отклоняться схемой или contract-тестом.
Каждая запись registry также задаёт допустимые `section/slug`; известный ключ,
назначенный другому уроку, должен отклоняться cross-field contract-тестом.

### LP-FR-007 Совместимая навигация

Главная страница, каталог, canonical и `hreflang` должны использовать
локализованный `href` опубликованной записи. Смена языка на парном уроке должна
сохранять `section`, `slug`, query и hash по правилам системной SPEC.

## 7. Нефункциональные требования

### LP-NFR-001 Статическая сборка

Все публичные маршруты формируются во время `astro build`; runtime backend для
разрешения уроков не требуется.

### LP-NFR-002 Индексируемость

Смысловой текст MDX не должен быть скрыт классом `sr-only` или целиком перенесён
в гидратируемый React-компонент.

### LP-NFR-003 Детерминизм

Manifest и списки маршрутов при одинаковом контенте должны быть
детерминированными и не зависеть от сетевых запросов.

## 8. Входные данные

- записи `src/content/lessons/**/*.{md,mdx}`;
- frontmatter: `language`, `section`, `slug`, `order`, `duration`, `draft` и
  optional `interactive`;
- curriculum с разделами и карточками тем.
- optional `lessonSlug` у curriculum-темы, явно связывающий карточку с
  публикацией внутри родительского section.

## 9. Выходные данные

- manifest опубликованных уроков;
- статические локализованные маршруты;
- derived `available` и `href` для карточек;
- статический HTML урока и optional hydrated island.

## 10. Основной сценарий

1. Автор добавляет согласованную RU/UK-пару MDX.
2. Схема и contract-тесты проверяют метаданные и optional interactive key.
3. Manifest включает обе опубликованные записи.
4. Главная и каталог помечают соответствующую карточку доступной и формируют её
   локализованный `href`.
5. Route отрисовывает видимый MDX и, если задано, разрешённый island.

## 11. Альтернативные сценарии

- если тема есть только в curriculum, карточка остаётся недоступной;
- если `interactive` отсутствует, урок остаётся полностью рабочим статическим
  MDX-маршрутом;
- если запись имеет `draft: true`, публичный маршрут и ссылка не создаются.

## 12. Ошибки и граничные случаи

- дублированный публичный ключ отклоняется contract-тестом;
- отсутствующая или draft-локаль отклоняет парную публикацию;
- неизвестный interactive key отклоняется до генерации production-страниц;
- известный interactive key на несовместимом `section/slug` отклоняется;
- отсутствующий или неверный `lessonSlug` оставляет карточку недоступной без
  fallback-ссылки;
- отсутствие записи manifest не заменяется ссылкой на `mesh-current-method`;
- наличие дополнительного MDX без island не должно требовать изменения route.

## 13. Контракт интерфейса

Минимальная запись manifest:

```ts
type PublishedLesson = {
  language: "ru" | "uk";
  section: string;
  slug: string;
  href: `/${"ru" | "uk"}/topics/${string}/${string}/`;
  interactive?: InteractiveKey;
};
```

Допустимый ключ первого этапа:

```ts
type InteractiveKey = "mesh-lesson";
```

Registry хранит не только компонент, но и совместимость публикации:

```ts
type InteractiveDescriptor = {
  section: "dc";
  slug: "mesh-current-method";
  component: unknown;
};
```

Конкретный модуль и дополнительные поля могут меняться без изменения SPEC,
если сохраняются требования и критерии приёмки.

## 14. Совместимость и миграция

- существующие URL `mesh-current-method` сохраняются;
- обе существующие MDX-записи получают одинаковый `interactive: mesh-lesson`;
- hardcoded mesh fallback удаляется только после появления manifest/resolver;
- визуальная структура legacy island сохраняется до отдельного этапа контента.

## 15. Критерии приёмки

- LP-AC-001: manifest содержит ровно фактически опубликованные записи обеих
  локалей и не содержит draft-записи;
- LP-AC-002: availability и `href` карточек выводятся из manifest, а не из
  hardcoded slug или ручного `available`; связь curriculum задана `lessonSlug`,
  а отсутствующее/неверное значение не получает fallback-ссылку;
- LP-AC-003: обычный MDX без `interactive` строится и отображается без
  `MeshLessonIsland`;
- LP-AC-004: `mesh-current-method` сохраняет существующий интерактив;
- LP-AC-005: неизвестный interactive key отклоняется;
- LP-AC-005a: известный interactive key на несовместимом `section/slug`
  отклоняется cross-field contract-тестом;
- LP-AC-006: основной MDX-текст присутствует в видимом статическом HTML;
- LP-AC-007: test/check/lint/build проходят без skip/disable.

## 16. Связь с тестами

| Требование | Проверка |
|---|---|
| LP-FR-001, LP-AC-001 | unit/contract-тест manifest |
| LP-FR-002, LP-AC-002 | тест resolver карточек, включая missing/wrong `lessonSlug`, и аудит generated HTML |
| LP-FR-003 | существующий content contract |
| LP-FR-004, LP-AC-003, LP-AC-006 | route contract и production build |
| LP-FR-005, LP-FR-006, LP-AC-004, LP-AC-005, LP-AC-005a | schema/registry и cross-field contract |
| LP-FR-007 | browser-тест локализованной навигации |
| LP-NFR-001, LP-AC-007 | `npm test`, `npm run check`, `npm run lint`, `npm run build` |
