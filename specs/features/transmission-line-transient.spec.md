# Интерактив переходного процесса в длинной линии

Статус: утверждённый contract по пользовательскому MASTER PROMPT от 2026-09-28.
Область: static RU/UK Electro Tutor, без backend и сохранения пользовательского state.

## Requirements

- `INT-009`: в разделе «Интерактив» три отдельные карточки и локализованные
  маршруты: круговая диаграмма четырёхполюсника, звезда с нейтралью, длинная
  линия. Круговая диаграмма получает отдельную страницу; встроенная версия
  на индексной странице остаётся для совместимости существующих share links,
  keyboard и RU/UK browser contracts.
- `LINE-001`: production physics — Rust/`wasm-bindgen` в одном Web Worker.
  Численный solver использует только текущее распределённое состояние,
  O(N) памяти и O(N) работы на шаг; ни список отражений, ни история кадров,
  ни analytic travelling-wave engine в расчёте не допускаются.
- `LINE-002`: однородная lossless линия длиной `l` из `N` ячеек с
  `V[0..N]`, `I[0..N-1]` (токи source→load) и отдельными per-cell `L`,
  per-node `C` с half-cell ёмкостью на концах. `L'=Z0/v`,
  `C'=1/(Z0v)`, `dx=l/N`, `dt=cfl·dx/v`; default CFL=0.9.
  Explicit staggered leapfrog обновляет токи, затем напряжения.
  Внутренние единицы SI, `f64`, непрерывные буферы.
- `LINE-003`: левый порт — DC step `Vs(t)` с `E`, `Rs`, `switchTime`.
  Для `Rs>0` граничный ток следует `(Vs−V0)/Rs`; для `Rs=0` действует
  идеальная Dirichlet-граница, без искусственного малого сопротивления.
  Текущий стартовый режим использует идеальный источник `Rs=0`: после прихода
  отражённой волны напряжение на левом конце остаётся равным `Vs`, поэтому
  возмущение напряжения отражается с `Γs=−1` и снова идёт к нагрузке.
  Это короткое замыкание только для приращения относительно установленного
  напряжения источника, не замена полного граничного напряжения нулём.
  При `Rs=Z0` возвращающаяся волна поглощается; конечное `Rs` остаётся
  доступным параметром для сопоставления режимов.
  Source port отделён от конкретной формы сигнала и может позже принять
  sinusoid/pulse/arbitrary waveform.
- `LINE-004`: правый порт — отдельная boundary-device abstraction.
  Поддержаны open, short, R, L, C, RL, RC, RLC; для смешанных нагрузок
  серия обязательна, parallel желательна. Состояние реактивных ветвей
  `iL`/`uC`, включая заданные initial values, сохраняется между шагами.
  API должен позволять future nonlinear residual `F(u,i,x,t)=0`,
  не внедряя MNA/Newton в MVP. Решение границы должно быть конечным,
  без отрицательных R/L/C и без surrogate open/short.
- `LINE-005`: конфигурация валидируется до запуска (конечные положительные
  `l,v,Z0,N`, пассивные параметры, конечное stop time, CFL≤0.95).
  Ошибки WASM/worker и численной неустойчивости видимы; нет подмены solver
  демонстрационной анимацией. Диагностика включает `dx,dt,CFL,τ`, порты,
  min/max V/I и энергию линии.
- `LINE-006`: worker владеет solver state, reset, step, play/pause, stop-at,
  fast-forward и deterministic seek. Seek назад = reset + повторное
  интегрирование; полная история не хранится. Physics `dt` не зависит от
  FPS и playback rate. Не более одного ожидающего render snapshot;
  промежуточные кадры можно отбрасывать.
- `LINE-007`: React UI показывает source/line/load параметры только по
  применимости, `U(x)` и `I(x)` через Canvas 2D, схему SOURCE→LOAD,
  текущие `t`, портовые значения и состояние нагрузки. Есть Play, Pause,
  Reset, Step, Stop At, seek и визуальный множитель скорости. Hover показывает
  `x,U(x),I(x)`. Большие массивы не проходят через React state.
- `LINE-008`: Rust reference tests: propagation near `τ=l/v`,
  `U/I≈Z0` до отражений, matched/open/short/mismatched R по аналитическим
  oracles, повторные отражения при идеальном источнике `Rs=0` после `2τ`
  и отсутствие возвратного отражения при `Rs=Z0`, C/L/RLC continuity/evolution,
  N=100/200/400/800 convergence
  по одинаковым физическим x/t, finite/energy stability, deterministic
  reset+seek, invalid inputs и O(N) memory. Browser E2E проходит оба
  сценария open/C/L с реальным WASM Worker и RU/UK.
- `LINE-009`: reproducible microbenchmark для N=1000/5000/10000 отдельно
  измеряет steps/s, simulated seconds/s, snapshot и worker transfer;
  результаты не обещают постоянную производительность на каждом устройстве.
- `LINE-010`: data layout и портовые interfaces не блокируют future
  spatial `R',L',G',C'`, неравномерный `dx[k]`, нелинейный one-port и
  общий transient circuit engine. Lossy/nonlinear/multiline mode не входит
  в MVP.

## Численная схема и границы

`I_k^{n+1/2}=I_k^{n-1/2}+dt/L_k·(V_k^n−V_{k+1}^n)`.
Для внутренних узлов
`V_k^{n+1}=V_k^n+dt/C_k·(I_{k−1}^{n+1/2}−I_k^{n+1/2})`.
Концы используют ту же ёмкость узла и токи портов. Пассивные linear
boundary devices дают midpoint companion `i=G·v_mid+b` плюс свой
минимальный state; интерфейс сохраняет место для nonlinear residual.
Вместо решения плотной глобальной системы вычисляется только локальная
формула каждого endpoint. `Rs=0` и short load — точные voltage constraints.

В default initial state все распределённые значения нулевые. При
ненулевом initial voltage идеального C terminal node должен начинать с
`uC(0)`, чтобы удовлетворить физическому voltage constraint; остальные
узлы остаются нулевыми. Reset возвращает согласованное initial state.

## Приёмка

Сценарий: `E=100 V, Rs=50 Ω, l=1000 km, v=2e8 m/s, Z0=50 Ω,
N=1000, open, stop=20 ms`. UI показывает `τ=5 ms`; фронт достигает
нагрузки около 5 ms, терминал меняется, затем пространственный pattern
возвращается к источнику. C и L load дают непрерывные state trajectories.
В отдельном стартовом сценарии с `Rs=0` и open load возвращение волны к
источнику около `2τ=10 ms` вызывает новую волну обратного знака; около
`3τ=15 ms` она доходит до нагрузки. При `Rs=Z0` такого повторного
прохождения нет.
Спецификация подтверждается Rust tests, собранным WASM Worker в Chromium,
quality gates и benchmark. UI/worker не объявляют completion при одной
статической или mock проверке.

Вне MVP: lossy и неоднородная линия, нелинейные приборы, circuit MNA/DAE,
WebGPU/threads/SharedArrayBuffer, сохранённые simulation checkpoints.


## V2 contract — утверждён прямым пакетом владельца2026-10-29

Новый primary UI supersedes прежний выбор presets/apply/numerical knobs (LINE-007) и обязательность только FDTD для primary path (LINE-001). Legacy Rust/WASM source и тесты сохраняются; точное lossless решение не маркируется FDTD. Старые сценарии buttons/apply описывают прежний UI и не заменяют V2 acceptance.

- `LINE-V2-001`: физическая модель отдельно от clock/render. Идеальные однородные участки с Z0,v,l; L′=Z0/v,C′=1/(Z0v). Ступенчатые фронты primary passive-resistive path вычисляются по временам задержек/граничным условиям без FDTD дисперсии/сплайнов; сохраняются промежуточные отражения и знак I=(U+−U−)/Z0.
- `LINE-V2-002`: constructor нескольких последовательных участков (включая2/3), истинный накопленный x и границы. Источник step/pulse, Rs и время коммутации; нагрузка строится поддерживаемыми соединениями компонентов/обрывом/проводом. У каждого поддерживаемого узла явные equations; несовместимая схема/параметр блокирует расчёт. Нельзя заявлять arbitrary circuit solver.
- `LINE-V2-003`: разрешённые физические edits автоматически пересчитывают начальную задачу с валидацией draft; нет Apply/CFL/cells/dt в основном UI. Live изменение поддерживаемого сопротивления/ключа создаёт событие с t/old/new и не переписывает прошлое; параметры самой линии только recalculate. Reactive RLC сохраняют initial/device states и не используют постоянный Γ.
- `LINE-V2-004`: preview experiment interval определяет диапазоны U/I, общие для связанных пространственных/временных графиков; locked default. MANUAL, one-shot FIT, restore, overflow indicator; t/speed/camera/probe/theme не меняют границы. Nice ticks, SI и локаль из src/engineering.
- `LINE-V2-005`: clock независимо от физики/FPS,1× default и log0,1–32× с number/−/+; speed edit без reset/t jump. Play/pause/resume/stop/reset/step backward/forward/next-event/seek/duration; bounded background/hidden motion, no timer accumulation.
- `LINE-V2-006`: topology view с нейтральными УГО, editing/move/grid/undo/redo/save где поддержано; схематические nets соответствуют solver. Probe x/t синхронно управляют U/I epures, U/I traces и дополнительной U(x,t) либо I(x,t) surface; fixed quantitative color scale/units/camera/2D fallback, no fake branch surface.
- `LINE-V2-007`: independent matched/open/short/impedance-step2/3sections oracles, arrival times, source reflections, KCL/power/energy incl stored energy, device initial states and convergence where numeric. Shared2D/3D values and unchanged axis/clock/speed states tested. No normative certification inferred from calculation.

Первый release охватывает исправления A и законченные поддерживаемые расширения B/C. Потери/плавная неоднородность/произвольные ветвления/nonlinear DAE остаются future и никогда не получают вымышленные результаты. Legacy numerical controls не нужны обычному пользователю V2.

## Визуальный конструктор линий

- LINE-UX-001. Схема открывается с рабочим опытом. Выбор мышью, касанием и клавиатурой показывает параметры объекта. Палитра и постоянная нижняя панель дают доступ к добавлению, истории, параметрам, воспроизведению, графикам и справке.
- LINE-UX-002. Единый pointer-жест показывает допустимые точки, ближайшую привязку и смещённый от пальца предпросмотр. Отпускание вне допустимой области, Escape и отмена указателя сохраняют модель. Выбор инструмента и активация маркера дают тот же результат.
- LINE-UX-003. Конец цепочки принимает согласованное R, R/L/C, разрыв или замыкание. Шунт размещается в свободном узле или в середине участка с разделением его на две секции одинаковых Z₀ и v. Новый участок продолжает цепочку в её конце. Источник перемещается между допустимыми узлами. Конструктор использует валидатор V2 и его предел 1–6 секций. При удалении секции соседние узлы объединяются. Затрагиваемые подключения требуют подтверждения, а коллизия двух шунтов блокирует удаление.
- LINE-UX-004. История хранит атомарные изменения модели и расположения. Подтверждённые конфигурации восстанавливаются через существующий локальный JSON. Справка и переход между панелями сохраняют текущее состояние. Предпросмотр не запускает решатель. Графики текущего опыта появляются после успешного ответа worker.
- LINE-UX-005. Рабочая область поддерживает панорамирование, колесо, pinch, подгонку и центрирование выбранного объекта. Палитра и панель учитывают малые экраны и safe-area. Приёмка включает Chromium с событиями мыши и touch, а также ручную проверку физического смартфона с экранной клавиатурой.

## Управление опытом и коммутация

- LINE-UX-006. Постоянная нижняя панель управляет стартом, паузой, остановкой и скоростью воспроизведения. Старт продолжает с текущего времени, Стоп возвращает к t = 0. Скорость по умолчанию ×1 и выбирается степенями двойки от ×1/16 до ×32. Точный выбор времени и переход к фронту доступны в раскрываемой части панели.
- LINE-UX-007. Параметры редактируются по выбору символа на схеме. Палитра, история и обмен JSON доступны на рабочем поле. Сложные параметры источника и нагрузки раскрываются на выбранном объекте. Требование нижней панели из LINE-UX-001 уточнено этим контрактом.
- LINE-UX-008. Для R геометрия различает последовательную вставку в промежуточный стык, шунт между сигнальным узлом и опорой, резистивную перемычку между двумя сигнальными узлами и концевую нагрузку. В середине распределённого участка вставка сохраняет суммарную длину, Z₀ и v. Подсветка и предпросмотр показывают фактические выводы. Выбор второго узла перемычки выполняется явно.
- LINE-UX-009. Идеальный ключ на последовательном стыке и ключ в резистивной ветви задают начальное состояние и одно необязательное событие открытия или закрытия в миллисекундах. Решатель обновляет граничные условия в момент события. Идеальный ключ в нагрузке использует существующую модель событий. Для RLC допускаются прежние стационарные топологии; совместная коммутация требует отдельной проверки непрерывности состояний и пока отклоняется валидатором.
- LINE-UX-010. Сохраняются прежний JSON и физические сценарии. Добавленные резистивные ветви поддерживают KCL, расчёт отражения и прохождения и не превращают распределённую линию в провод. Разветвление распределённых линий потребует явного графа путей и пространственных измерений. Текущая цепочка секций и фактические резистивные ветви остаются доступными.

## Единая палитра, геометрия и нелинейная нагрузка

- LINE-UX-011. Обычное колесо прокручивает страницу, Ctrl+колесо масштабирует около указателя. Pinch, панорамирование и вписывание остаются доступны. Эпюры автоматически выбирают диапазон. Геометрическое перемещение и явное переподключение являются разными действиями с общей историей.
- LINE-UX-012. Палитра содержит линию, провод, R/L/C, источник ЭДС, ключ и диод. В режиме размещения видны символ, допустимые выводы и состояние инструмента. Мышь и касание используют те же проверенные операции, Escape завершает размещение.
- LINE-UX-013. Провода, R/C, L, диод и ключ ориентированы на ГОСТ 2.721/2.728/2.723/2.730/2.755. Линия отличается толщиной, стрелка ЭДС определяется знаком напряжения, полярность диода видна в символе. Положение нагрузки на вертикальной ветви по умолчанию центральное.
- LINE-UX-014. Концевой диод рассчитывается по ВАХ Шокли без пробоя и накопления заряда. Узловое уравнение решается монотонно с эквивалентом Тевенина сети, с учётом существующих резистивных связей и событий. ВАХ показывает текущие U/I в направлении анод–катод. Вложенные нелинейные сети и диод в промежуточном стыке требуют отдельной модели. Исходная цепочка поддерживает один источник, который можно разместить в другом узле.

## Стационарные потери без дисперсии

- LINE-LOSS-001. Первый режим распределённых потерь поддерживает условие Хевисайда R′/L′ = G′/C′ для каждого участка. Сохраняются прежние Z₀ и скорость. Интерфейс задаёт R′ и показывает вычисленные L′, G′ и C′ в SI. R′ = 0 восстанавливает прежний расчёт.
- LINE-LOSS-002. В прямой и обратной волнах множитель exp(−R′d/Z₀) применяется на пройденном расстоянии d. Учитываются задержка, отражение, показания порта, графики и энергия. Поверхность с потерями визуализируется численно. Эталоны — согласованная линия, открытый конец и секции с разными потерями. Независимые R′/G′, дисперсия и подвижные границы требуют отдельной модели.

## Контекстный монтаж и длинный эксперимент

- LINE-UX-019. Очистка требует диалога с отменой и полностью удаляет содержимое текущего рабочего поля. Пустое поле сохраняется в черновик и JSON, не отправляется в решатель, восстанавливается Undo. Первая линия начинает поддерживаемую модель с открытым концом.
- LINE-UX-020. Выбор двухполюсника подсвечивает выводы и позволяет указать первый и второй узел напрямую. Указание участка линии вставляет элемент последовательным разбиением. Совместимая идеальная перемычка заменяется вставленным элементом. Обычное перемещение сохраняет топологию.
- LINE-UX-021. Контекстные действия вращения и свойств доступны на схеме. Геометрический поворот сохраняет выводы и записывается в историю. Предусмотрены клавиатурные действия и очистка выделения.
- LINE-UX-022. Эксперимент на 1 секунде проверяется на эталонах отражения и реактивного граничного условия. Численный шаг определяется физикой, хранилище ограничено; график использует отдельный бюджет с сохранением экстремумов и временным окном. Отмена завершает Worker, а прогресс измеряется выполненными шагами. Интерфейс показывает длительность в мкс, мс и с, оценку нагрузки и причину отказа.

## Ортогональная трассировка концевой нагрузки

- LINE-UX-023. Геометрия и электрическая модель остаются независимыми. Перетаскивание и поворот одиночной концевой нагрузки перестраивают два вывода, не меняя схему, параметры, начальные условия и ревизию расчёта. Трассировка проверяет корпуса и подпись нагрузки, не допускает пересечения или наложения двух проводов. Если допустимого маршрута нет, сохраняется предыдущее положение.
- Приёмка: регрессия на перетаскивание выше сигнального узла, сетка направлений и поворотов, проверка Undo/Redo и отсутствия пересчёта. Для составных нагрузок и других элементов требуется следующий отдельный срез.

- LINE-UX-025. Для перемещаемых и поворачиваемых элементов составной нагрузки, источника, линии, последовательных вставок и шунтирующих ветвей трассировка сохраняет исходные пары выводов. Геометрическая операция с невозможной локальной трассировкой отменяется. Узлы и параметры расчётной модели сохраняются в JSON после перемещения и Undo/Redo.

- LINE-UX-026. Основная панель показывает ход расчёта и диагностику ошибок. Служебная надпись о числе фронтов, повторный статус готовности и ссылка на измерения под схемой удалены. Анонс MCP находится вне холста.

- LINE-UX-027. При перестройке ветвей учитываются уже проложенные проводники. Касание допускается только в соответствующем узле, наложение сегментов запрещено. Электрическая модель не выводится из пересечений.
- LINE-UX-028. Длительность вводится вместе с единицей и сохраняется в секундах. Экспорт измерений JSON/CSV содержит полный ряд сохранённых отсчётов для выбранной точки независимо от масштаба графика. JSON включает схему, начальные условия, время и единицы.

## Панель опыта и результаты

- LINE-UX-029. В транспортной панели «Пуск» показывает индикатор только во время вычисления. Пауза сохраняет физическое время, стоп возвращает его к нулю. Отмена и повтор расчёта остаются доступны. Масштаб временных графиков находится в раскрываемой панели времени. Основная страница не содержит 3D-поверхность, таблицу истории событий и блок описания модели. События остаются в расчёте и экспортируются с параметрами схемы. Измерения и четыре плоских графика доступны после успешного расчёта. Компактный экспорт объединяет JSON, CSV и SVG эпюры напряжения.

- LINE-UX-030. The existing line editor accepts local pointer strokes and proposes a symbol at the end of each stroke. Review and explicit correction precede the normal placement flow. Unmarked straight strokes are wires. A line requires two endpoint taps followed by a straight stroke joining them. For an existing chain, one marked endpoint must touch its last node. The created section has editable physical parameters and the schematic retains the marked endpoints.
- LINE-UX-031. Recognition geometry, network topology and display conventions are separate. A rectangular and a zigzag resistor represent the same component. The display selector changes the resistor glyph throughout the line schematic. Recognized junctions and ground require an explicit connection to existing network nodes. A drawn source can replace the existing reference-connected excitation with a voltage or independent current source. Additional independent sources and free-form graphs are outside this solver scope.
- LINE-UX-032. Accepted stroke samples, layout and network share the existing local save, JSON and undo/redo document. Reject invalid or unroutable edits before changing topology. Crossing ink never creates a connection. Test geometric variants, rotated and noisy input, network validation, state restoration and the real line solver.
- LINE-UX-033. A saved mark can be reopened from the ink archive, redrawn and confirmed or cancelled. Linked corrections update the original object and preserve terminal connectivity. Keep physical parameters for the same type. Validate electrical changes and routing before applying them. Commit a correction as one history entry. Save associations with the document. Older unlinked marks remain editable as ink without changing circuit objects.

## Цвета пространственных эпюр

- LINE-UX-024. На эпюрах U(x) и I(x) прямая составляющая красная, обратная зелёная, сумма синяя. Легенда и SVG используют цвета соответствующих кривых.

## Свободная компоновка и двухполюсные элементы

- LINE-UX-015. Перетаскивание задаёт координаты X/Y в системе схемы. Проводники следуют за символами. Компоновка и неподключённые элементы входят в историю и черновик и не отправляются в Worker.
- LINE-UX-016. Элемент палитры на пустом поле становится неподключённым. Команда «Подключить» или «Переподключить» позволяет выбрать допустимые выводы, сохраняя параметры. Предпросмотр и отмена не меняют расчётную схему. Доступны последовательная вставка, ветвь к опоре и выбор двух сигнальных узлов.
- LINE-UX-017. L/C в промежуточном стыке или ветви рассчитываются методом характеристик с трапецеидальной моделью между выбранными выводами. Начальные условия и энергия входят в расчёт. Ветвевые диоды используют Shockley, включая несколько связанных диодов и сочетание с L/C. Неустойчивый или несовместимый расчёт сообщает ошибку. Прежний запрет на запланированную коммутацию с накопителями энергии сохраняется.
- LINE-UX-018. Формат v5 хранит свободную компоновку и новые элементы. v2–v4 импортируются с исходной топологией. Приёмка включает численные эталоны, реальный Worker, мышь, touch и восстановление состояния.
