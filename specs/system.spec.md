# Системная спецификация «Потенциал»

Статус: Действует

Версия: 1.0

## 1. Назначение

«Потенциал» (`electro-tutor`) — двуязычная образовательная веб-платформа по
электротехнике с индексируемыми уроками, формулами, схемами и интерактивными
расчётными инструментами.

## 2. Область

- публичный статически генерируемый сайт;
- русская и украинская локали с техническими кодами `ru` и `uk`;
- каталог и уроки по электротехнике;
- три уровня подробности решения;
- интерактивные расчётные инструменты;
- PWA-возможности;
- MVP кабинета онлайн-занятия;
- витрина услуг и необязательная ссылка на внешнее расписание.

## 3. Вне области текущей версии

- собственные аккаунты и авторизация;
- серверное хранение прогресса, файлов или состояния доски;
- собственная видеосвязь;
- реализованные платежи и хранение платёжных данных;
- автоматическая публикация без отдельного разрешения пользователя.

## 4. Участники

- ученик читает уроки и пользуется интерактивом;
- преподаватель публикует материалы и проводит онлайн-занятия;
- поисковый робот индексирует статический учебный текст;
- разработчик поддерживает согласованность локалей и контента.

## 5. Функциональные требования

### FR-001 Локализация

Каждая публичная индексируемая страница должна иметь версии `/ru/` и `/uk/` с
эквивалентной навигацией. Пользовательская метка украинского языка может быть
`UA`, но внутренний код локали остаётся `uk`.

### FR-002 Учебные материалы

Опубликованный урок должен хранить индексируемый текст в Content Collections и
иметь парные RU/UK-файлы с одинаковыми `section` и `slug`. Метаданные должны
соответствовать схеме `src/content.config.ts`; записи с `draft: true` не должны
попадать в публичные маршруты.

### FR-003 Каталог

Каталог не должен предлагать рабочую ссылку на урок, для которого нет
опубликованного контента соответствующей локали. Карточка темы сама по себе не
считается опубликованным уроком.

### FR-004 Уровни объяснения

Решаемые учебные задачи должны поддерживать три уровня: полный вывод,
объяснение ключевых шагов и краткое решение. Выбранный уровень сохраняется в
браузере.

### FR-005 Формулы и схемы

Формулы отображаются через KaTeX. Схемы должны быть читаемы в обеих темах,
иметь прозрачный фон и сохранять смысловые цвета токов и напряжений.

### FR-006 Интерактив

Расчётный инструмент круговой диаграммы должен принимать числовые параметры,
корректно обрабатывать вырожденную точку и сохранять воспроизводимое состояние
в query-параметрах URL.

### FR-007 Интерфейс

Светлая/тёмная тема сохраняется локально. Переключение языка должно сохранять
query, hash и позицию просмотра, когда маршрут имеет парную локализацию.

### FR-008 PWA

Сайт предоставляет manifest, иконки, регистрацию service worker и
offline-страницу. Изменение стратегии кэша требует изменения версии кэша.

### FR-009 Кабинет занятия

MVP кабинета создаёт или принимает безопасно нормализованный код комнаты,
формирует ссылку-приглашение и подключает публичный Jitsi только после явного
действия пользователя. Камера и микрофон по умолчанию выключены.

### FR-010 Расписание

Если `PUBLIC_CALCOM_URL` не задан, интерфейс показывает нейтральное сообщение о
будущей интеграции. Если переменная задана, интерфейс открывает внешнюю страницу
расписания без передачи секретов.

## 6. Нефункциональные требования

### NFR-001 Сборка

Проект использует Node.js `>=22.12.0` согласно `package.json` и должен успешно
проходить настроенные `check`, `lint` и `build`.

### NFR-002 SEO

Публичные страницы должны содержать корректные `title`, `description`,
canonical и `hreflang`. Production-сборка должна получать точный `SITE_URL`, а
не публиковаться с резервным доменом `electrotutor.example`.

### NFR-003 Адаптивность и доступность

Основные сценарии должны быть доступны с клавиатуры и на экранах шириной от
мобильной до настольной. Интерактивные SVG имеют текстовое описание.

### NFR-004 Безопасность

Секреты и ключи не хранятся в `src/`, `public/` или Git. Внешние интеграции и
платежи подчиняются `docs/SECURITY.md`.

### NFR-005 Кодировка

Текстовые файлы хранятся в UTF-8 без BOM с переводами строк LF.

### NFR-006 Неблокирующая загрузка внешних шрифтов

Недоступность или зависание Google Fonts не должны задерживать первый рендер
основного содержимого. Страница сначала отображается системными fallback-шрифтами,
а `DM Sans` и `Manrope` подключаются только как progressive enhancement.

## 7. Основной сценарий

1. Пользователь открывает `/ru/` или `/uk/`.
2. Выбирает тему в каталоге.
3. Открывает опубликованный урок или интерактивный инструмент.
4. При необходимости меняет язык, тему и уровень подробности без потери
   поддерживаемого состояния.

## 8. Критерии приёмки

- AC-001: сборка создаёт статические RU/UK-маршруты без ошибок.
- AC-002: для каждого опубликованного урока существует парная локаль.
- AC-003: каталог не ведёт отсутствующие темы на чужой урок.
- AC-004: canonical/hreflang формируются от production `SITE_URL`.
- AC-005: состояние интерактива воспроизводится из URL после перезагрузки.
- AC-006: секреты отсутствуют в клиентском bundle и публичных файлах.
- AC-007: `npm run check`, `npm run lint` и `npm run build` завершаются успешно.
- AC-008: при удерживаемом запросе `fonts.googleapis.com` основной `h1` становится
  видимым без ожидания ответа внешнего сервиса.

## 9. Связь с проверками

| Требование | Проверка |
|---|---|
| FR-001, FR-002, NFR-002 | `npm run build` и аудит сгенерированных маршрутов |
| FR-006 | будущие unit-тесты математической модели и browser-тест query state |
| FR-007, NFR-003 | browser-проверка темы, языка, клавиатуры и responsive |
| NFR-001 | `npm run check`, `npm run lint`, `npm run build` |
