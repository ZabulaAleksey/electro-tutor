# Текущий AI-план

Статус: готов к запуску

Roadmap: `ET-01.1 — Восстановить штатные проверки`

SPEC: `../specs/system.spec.md` (`NFR-001`, `AC-007`)

## Цель

Сделать `check`, `lint` и `build` воспроизводимыми без интерактивных запросов и
ошибок конфигурации.

## Наблюдаемая исходная точка

- `npm run check` предлагает интерактивно установить `@astrojs/check` и не
  выполняет фактическую проверку;
- `npm run lint` завершается ошибкой, потому что ESLint 9 не находит flat config;
- production build ещё нужно повторно подтвердить после исправлений.

## Область

- `package.json` и lockfile;
- минимальная ESLint 9 flat config;
- только необходимые исключения generated/legacy областей, если они
  обоснованы фактическими ошибками;
- команды и краткая документация, если их контракт изменится.

## Вне области

- исправление продуктовых функций;
- большой рефакторинг legacy React;
- выбор test runner и написание unit-тестов (`ET-01.2`);
- deploy, merge и внешние записи.

## Шаги

1. Зафиксировать версии Node/npm и полный вывод трёх команд.
2. Добавить `@astrojs/check` как dev dependency штатной командой package manager.
3. Создать минимальный `eslint.config.*` для TypeScript/React/Astro либо явно
   ограничить lint файлами, которые поддерживает установленный parser.
4. Исправить только реальные ошибки, мешающие базовой проверке; не маскировать
   их широкими disable.
5. Выполнить `npm run check`, `npm run lint`, `npm run build` и
   `git diff --check`.
6. Сверить результат с NFR-001/AC-007, обновить `AI_STATUS.md`, закрыть ET-01.1
   в `ROADMAP.md` и подготовить следующий ограниченный `AI_PLAN`.

## Критерии приёмки

- команды не требуют интерактивной установки;
- все три npm-проверки завершаются с code 0;
- generated `dist/` и `.astro/` не попадают в commit;
- изменения не меняют наблюдаемое поведение сайта;
- commit содержит один логический этап.

## Откат

Один commit этапа можно отменить без миграции данных или изменения production.
