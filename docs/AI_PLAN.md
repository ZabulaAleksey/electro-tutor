# Текущий AI-план

Статус: готов к выполнению

Roadmap: `ET-02 — Единая модель публикации уроков`

SPEC: `../specs/features/lesson-publishing.spec.md`; базовые требования —
`../specs/system.spec.md` (`FR-002`, `FR-003`, `AC-002`, `AC-003`).

## Цель

Сделать Content Collection единым источником опубликованных уроков, маршрутов и
доступности каталога, а специализированный React island подключать только по
явному проверяемому ключу frontmatter.

## Предусловие

`ET-01` завершён: test/check/lint/build проходят, `npm audit` сообщает 0
известных уязвимостей.

## Область

- зафиксировать feature-SPEC и критерии приёмки модели публикации;
- добавить типизированный ключ optional interactive island в frontmatter;
- построить единый manifest опубликованных RU/UK-уроков;
- вывести доступность и ссылки каталога из manifest;
- сделать маршрут урока универсальным для MDX и optional island;
- покрыть manifest, каталог и маршруты contract-тестами.

## Вне области

- создание новых учебных материалов без выбора пользователя (`ET-03`);
- редизайн страниц и новые интерактивные инструменты;
- аккаунты, платежи, booking и production deploy.

## Шаги

1. Расширить frontmatter типизированным optional ключом и добавить статический
   registry допустимых islands.
2. Построить manifest опубликованных уроков с проверяемым resolver.
3. Удалить жёсткие ссылки карточек на `mesh-current-method`, выводя доступность
   и `href` из manifest.
4. Сделать универсальный MDX route с optional island и добавить contract-тесты.
5. Выполнить test, check, lint, build и browser-проверку в рамках `ET-04`.

## Критерии приёмки

- опубликованный парный RU/UK-урок автоматически получает корректные маршруты;
- карточка доступна только при наличии опубликованной пары и ведёт на свой slug;
- обычный MDX-урок отображается без обязательного `MeshLessonIsland`;
- неизвестный interactive key отклоняется схемой или проверкой сборки;
- существующий `mesh-current-method` и его интерактив сохраняются;
- test/check/lint/build проходят без skip/disable.

## Откат

Каждый подэтап оформляется отдельным commit и может быть отменён без миграции
данных или изменения production.
